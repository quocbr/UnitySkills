# Unified Unity workflows

Read the section for the requested capability. Official references define Unity workflows and design constraints. Nice Wolf Studio's Unity 6.3 references provide code patterns and review cases. The gamedev guides add design and diagnostic workflows. Check the project's Unity and package versions before applying examples. Resolve a guide's supporting files from its own directory and follow the routes below when it names another skill. Use Besty references and the Workbench Editor protocol for live operations.

## C# implementation and code review

First identify the requested outcome and the project's Unity version, resolved packages, assembly definitions, and relevant scripting defines. Read the affected source, callers, and tests. When behavior depends on serialized fields, inspect the owning scene, prefab, or asset too. Trace the path from the entry point through state ownership to the visible effect before changing code. Use [scripting](nice-wolf-studio/unity-scripting/GUIDE.md) and [Unity foundations](nice-wolf-studio/unity-foundations/GUIDE.md) for the APIs and object model; apply Unity 6.3 examples only when the target version and packages support them.

For code using `UniTask`, check the resolved `com.cysharp.unitask` version and load [UniTask design](../skills/unitask-design/GUIDE.md) for cancellation, PlayerLoop timing, composition, and conversion rules. Use [async strategy](../skills/async/GUIDE.md) when choosing between UniTask, Unity `Awaitable`, coroutines, and `Task`; do not add a package solely because a guide describes it.

For C# using packages such as Netcode for GameObjects, Addressables, or YooAsset, check the resolved package version and read its matching design guide in the [module catalog](../skills/GUIDE.md) before editing. For gameplay implementation, also open the matching gameplay section below.

| Request | Route and expected result |
| --- | --- |
| **Write a script or feature** | Define the behavior, owner, data lifetime, and integration points. Use [script design](../skills/scriptdesign/GUIDE.md) for class and field responsibilities, [architecture](../skills/architecture/GUIDE.md) when several systems change, and [Inspector design](../skills/inspector/GUIDE.md) for authored fields. Implement the smallest coherent change and check its callers and serialized bindings. |
| **Debug a failure** | Establish the expected and observed behavior, find the entry point and first incorrect state, then fix the cause. Check [lifecycle](nice-wolf-studio/unity-lifecycle/GUIDE.md) for initialization, destruction, and scene transitions; [async patterns](nice-wolf-studio/unity-async-patterns/GUIDE.md) for cancellation and thread context; and [3D math](nice-wolf-studio/unity-3d-math/GUIDE.md) for space, rotation, or projection errors when relevant. |
| **Review code** | Keep the review read-only. Follow the relevant call path; use [script design](../skills/scriptdesign/GUIDE.md) to check ownership and coupling, and [C# review checks](coding-review.md) for focused safety and performance questions. Report actionable findings by severity, with file locations, evidence, and the consequence. Mark uncertainty when the scene, package state, or runtime behavior has not been observed. Do not turn a general checklist into unsupported findings. |
| **Refactor** | State the behavior and public contract to preserve. Check callers, serialized field names, assembly boundaries, scene and prefab references, and tests before moving or renaming code. Use [script design](../skills/scriptdesign/GUIDE.md) and [pattern selection](../skills/patterns/GUIDE.md) only where they clarify ownership or reduce coupling. Verify the same behavior after the change. |
| **Write or run tests** | Use [test patterns](nice-wolf-studio/unity-testing/GUIDE.md) to choose Edit Mode for pure logic or Editor behavior and Play Mode for frame, physics, lifecycle, or scene behavior. Cover the reported regression or a meaningful boundary; run the smallest relevant check and report the actual result. For execution, use the test backend selected under [CLI, Pipeline, tests and builds](#cli-pipeline-tests-and-builds). |

Use ordinary workspace source editing for requested code changes. For a focused review of changed `.cs` files, apply the relevant [C# review checks](coding-review.md) and confirm any candidate finding in context. Use [script operations](../skills/script/GUIDE.md) when the task specifically needs the running Editor to read or write a script; inspect their mode restrictions before a write. Handle a blocked Editor operation through the [Editor protocol](../EDITOR.md); do not switch surfaces solely to evade its policy. After a source change, check compilation and the behavior or regression that motivated it using an available permitted backend. If no Editor or build backend is available, report which checks remain unverified.

When creating, moving, renaming, or deleting files under `Assets/` or an embedded package outside the Editor, keep each existing `.meta` with its asset. For a Unity project with `Assets/` and `ProjectSettings/`, use the read-only [asset integrity check](asset-integrity.md) to inspect GUIDs and serialized script references before import; investigate findings in context. A source scan does not replace Unity import, compilation, or scene verification.

For custom authoring tools, use [Editor tooling patterns](nice-wolf-studio/unity-editor-tools/GUIDE.md) for inspectors, serialization, Gizmos, and EditorWindows. Choose the UI framework below before writing the visual layer.

## Gameplay architecture and content design

- Use [game architecture](nice-wolf-studio/unity-game-architecture/GUIDE.md) and [state machines](nice-wolf-studio/unity-state-machines/GUIDE.md) to decide ownership, transitions and test boundaries. Use [game loops](nice-wolf-studio/unity-game-loop/GUIDE.md) to specify session flow, win/loss, progression and pacing.
- Use [data-driven design](nice-wolf-studio/unity-data-driven/GUIDE.md) to separate authoring data from runtime state and [save systems](nice-wolf-studio/unity-save-system/GUIDE.md) for persistence, migration and recovery. For scene transitions and Addressables lifetimes, use [scenes and asset loading](nice-wolf-studio/unity-scene-assets/GUIDE.md) with [the Addressables operations](../skills/addressables/GUIDE.md).
- For ScriptableObject data, read [asset patterns](nice-wolf-studio/unity-scripting/references/scriptableobjects.md). Use [ScriptableObject event channels and runtime sets](gamedev-agent-skills/unity/unity-scriptableobjects/GUIDE.md) when decoupling scene objects or sharing live state. Check whether each field is authored configuration, shared runtime state, or saved progress. Check Enter Play Mode Options before relying on `OnEnable` to reset runtime state. For live inspection or editing, use [ScriptableObject operations](../skills/scriptableobject/GUIDE.md).
- Use [NPC behavior](nice-wolf-studio/unity-npc-behavior/GUIDE.md) for perception and decisions, [level design](nice-wolf-studio/unity-level-design/GUIDE.md) for encounters and checkpoints, and [procedural generation](nice-wolf-studio/unity-procedural-gen/GUIDE.md) for seeded content and generation constraints. Use the live Editor only for requested inspection or supported authoring after choosing the design.
- For branching NPC dialogue, barks, and conditional choices, start with [dialogue systems](gamedev-agent-skills/disciplines/dialogue-systems/GUIDE.md). Check which dialogue package or runner the project uses, and use [Unity Localization](unity-technologies/localize-unity-project/GUIDE.md) for translated text and locale handling. When testing in Play Mode, check dialogue branches and their UI.

## Game feel, cameras and platformers

- **Impact and feedback.** Open [game feel](gamedev-agent-skills/disciplines/game-feel/GUIDE.md) for hits that feel weak, camera shake, hit-stop, easing, squash and stretch, or layered sound and particles. For hit-stop, use an unscaled timer, preserve the time scale from before the first overlapping effect, and define when it is restored. In Play Mode tests, trigger the effect repeatedly and verify that feedback returns to rest.
- **Camera movement.** Use [camera systems](gamedev-agent-skills/disciplines/camera-systems/GUIDE.md) for follow, dead zones, look-ahead, framing, orbit or split-screen. Check the current rig and use [Cinemachine patterns](nice-wolf-studio/unity-cinemachine/GUIDE.md) when the package is installed. Reproduce jitter with the same update timing and target motion before adjusting damping.
- **Platformer controls.** Use [platformer](gamedev-agent-skills/genres/platformer/GUIDE.md) for jump height, coyote time, input buffering, variable jump height and moving platforms. Use the [input workflow](#input-and-ecsdots) for the active input backend and [2D physics](unity-technologies/create-2d-physics/GUIDE.md) for collisions. Measure jump height and timing at the project's physics step.

## Input and ECS/DOTS

- Identify the active input backend, installed `com.unity.inputsystem` version, and existing `.inputactions` assets before editing. Use [Input System](nice-wolf-studio/unity-input/GUIDE.md) to implement actions, devices and rebinding when that backend is in use. Use [input correctness](nice-wolf-studio/unity-input-correctness/GUIDE.md) to review control schemes, action phases, rebinding persistence and local multiplayer devices.
- Use [ECS/DOTS](nice-wolf-studio/unity-ecs-dots/GUIDE.md) for Entities, Jobs, Burst, baking and SubScenes. Check the installed package versions and distinguish Entities workflows from GameObject authoring before selecting an API.

## UI and text

Identify the framework from explicit requirements or the existing scene and source. Use the [UI framework guide](unity-technologies/ui/GUIDE.md) for ambiguous menus, HUDs and editor panels.
Use [UI patterns](nice-wolf-studio/unity-ui-patterns/GUIDE.md) for screen flow, dynamic lists, HUD state or transitions and [Unity 6.3 UI examples](nice-wolf-studio/unity-ui/GUIDE.md) for implementation details after choosing the framework.

Use [game UI/UX](gamedev-agent-skills/disciplines/game-ui-ux/GUIDE.md) for safe areas, resolution scaling, HUD readability and gamepad focus. Verify the layout and navigation at the target aspect ratios and with the intended input devices.

- **UI Toolkit** (`.uxml`, `.uss`, `UIDocument`, `CreateGUI`). Use the [authoring guide](unity-technologies/ui-uitk/GUIDE.md) for layout, controls and runtime bindings. In an open Editor, use [the UI Toolkit operations](../skills/uitoolkit/GUIDE.md) to inspect existing files and documents, then create or update only the needed UXML, USS, `PanelSettings` or document. Verify the assigned visual tree and panel settings and, for runtime UI, verify its binding in the actual panel.
- **uGUI** (`Canvas`, `RectTransform`, prefab UI). Use the [uGUI guide](unity-technologies/ui-ugui/GUIDE.md) to design hierarchy, anchors and layout. Use [the uGUI operations](../skills/ui/GUIDE.md) to inspect and edit scene controls. Use [prefab operations](../skills/prefab/GUIDE.md) when the target is a prefab asset. Verify anchors and parent layout at the target aspect ratios.
- **IMGUI** (`OnGUI`, `OnInspectorGUI`). Follow [the IMGUI guide](unity-technologies/ui-imgui/GUIDE.md) for editor C# code. If updating via the running Editor, use [the script operations](../skills/script/GUIDE.md) and check compilation. uGUI operations apply to Canvas objects and UI Toolkit operations apply to UXML, USS and visual elements.
- For multilingual text or font issues, use [Localization](unity-technologies/localize-unity-project/GUIDE.md) or [TextMeshPro optimization](unity-technologies/optimize-text-mesh-pro/GUIDE.md) with the applicable UI framework above.

## CLI, Pipeline, tests and builds

Use [the official Unity CLI guide](unity-technologies/unity-cli/GUIDE.md) for Editor and license management, independent CLI tasks, and CI. Check the installed binary's `--version` and relevant `--help` before selecting arguments. Use [the Pipeline guide](unity-technologies/unity-pipeline/GUIDE.md) when the task requires Pipeline commands or a connected Player and the matching package is available.

For Unity Build Automation, use [Cloud Build](unity-technologies/manage-cloud-build/GUIDE.md) to configure build targets or diagnose failed cloud jobs. Confirm the Unity Cloud project and build target before issuing commands against them.

When a player build or download is too large, use [Unity build size](gamedev-agent-skills/unity/unity-build-size/GUIDE.md) to identify the largest contributors in a Build Report and select platform-specific fixes. Compare builds for the same target and settings.

Use [test patterns](nice-wolf-studio/unity-testing/GUIDE.md) to choose Edit Mode or Play Mode and make the regression observable. Use [platform builds](nice-wolf-studio/unity-platforms/GUIDE.md) for Build Profiles, platform defines, mobile targets and IL2CPP. When an installed CLI command behaves differently from its reference, consult the [CLI contract](nice-wolf-studio/unity-cli-contract/GUIDE.md) and [surface preflight](nice-wolf-studio/unity-surface-preflight/GUIDE.md) for diagnostic ideas. Use the Workbench's own CLI and Editor protocol above for execution, dependency setup, and permission decisions. Treat the upstream CLI examples as versioned observations.

For a player build, confirm the selected Build Profile's Scene List (or the global list when the profile has none), target platform and scripting backend before building. When using `BuildPipeline.BuildPlayer`, inspect its `BuildReport`; for any backend, check the actual result and logs. Build Addressables content when the project requires it, then launch the resulting player when the environment allows. Report separately when a build succeeded but player launch was not verified.

For Besty-mediated cold start or headless test, run or build, first check the bound project's `Library/UnitySkills/cli_config.json`. Use its `cliPath` and the applicable feature switch as described in [the bound-project CLI reference](../skills/unity-cli/GUIDE.md). Confirm Editor liveness and its project lock before opening or launching a second process. The cold-start marker can start the REST server and belongs only in the opt-in Besty workflow. When the target Editor is already running and REST is available, use [Editor operations](../skills/editor/GUIDE.md) and [Test Runner operations](../skills/test/GUIDE.md) for supported live work. Report actual test/build results from the chosen backend.

For a new game or prototype, use [the project bootstrap guide](unity-technologies/new-unity-project/GUIDE.md). Its delegated Workbench guides are already under `references/unity-technologies/`. Read them in place and skip installing or mirroring separate copies. Use [game polish](unity-technologies/craft-game-floors/GUIDE.md) for a first playable experience and [Web optimization](unity-technologies/optimize-web/GUIDE.md) for WebGL/WebGPU targets.

## Unity Package Manager

Read [the UPM guide](unity-technologies/unity-package-management/GUIDE.md) for package IDs, compatible versions and headless approaches. For an open Editor, use [the package operations](../skills/package/GUIDE.md) to inspect the installed state and dependencies. `package_search` searches the installed cache. Use the official registry discovery workflow when the requested package is absent from that cache.
Use [package and services examples](nice-wolf-studio/unity-packages-services/GUIDE.md) for project integration and use the project's resolved package versions for API details.

Choose the headless or live write path according to the Editor state, available tools and permissions. For an open Editor use the supported Besty operation only when allowed by its schema and mode. Wait for any reload and verify both the resolved version and project manifest or lockfile. A blocked REST mutation is handled through its policy flow.

## Navigation and physics

- **NavMesh.** Follow [AI Navigation](unity-technologies/initialize-ai-navigation/GUIDE.md) to choose surfaces, agents, links, and the right package. Check whether `com.unity.ai.navigation` is installed before using `NavMeshSurface` or `NavMeshLink`. For a running Editor, use [NavMesh operations](../skills/navmesh/GUIDE.md) for supported bake, agent, obstacle or path work. Verify the agent can query a route on the intended surface with the correct agent type and area mask. Author missing surface/link features with the version-appropriate Unity API.
- **3D collisions and queries.** On Unity 6000.3 or later, use [the PhysX diagnosis guide](unity-technologies/fix-3d-physics-collisions/GUIDE.md) to check layers, colliders, Rigidbody and callback setup. For earlier versions, use [physics query correctness](nice-wolf-studio/unity-physics-queries/GUIDE.md) alongside the installed Editor's API. Use [physics operations](../skills/physics/GUIDE.md) and [component inspection](../skills/component/GUIDE.md) to check the live scene and run targeted 3D queries. Verify runtime collision callbacks in Play Mode when authorized.
- **2D physics.** Select the appropriate system with [2D physics](unity-technologies/create-2d-physics/GUIDE.md). Use component inspection where supported and the chosen system's own API for 2D physics queries and callbacks.
- Use [physics examples](nice-wolf-studio/unity-physics/GUIDE.md) and [physics query correctness](nice-wolf-studio/unity-physics-queries/GUIDE.md) for movement, query type, hit order, masks and triggers. Use [navigation and inference](nice-wolf-studio/unity-ai-navigation/GUIDE.md) for runtime NavMesh logic and Sentis inference with the corresponding package.

## Rendering, Shader Graph and post-processing

- **URP post-processing.** Use [the URP post-processing guide](unity-technologies/urp-postprocessing/GUIDE.md) to diagnose camera settings, volume layers, profiles, and overrides. Read [the Volume operations](../skills/volume/GUIDE.md) to find the profile and [the effect operations](../skills/postprocess/GUIDE.md) for supported parameters. Confirm whether the profile is shared before editing. Verify override state and the effect in the target camera.
- **URP conversion or Renderer Features.** Use [the migration guide](unity-technologies/migrate-birp-to-urp/GUIDE.md) for Built-in to URP conversion and [the Render Graph review guide](unity-technologies/validate-urp-render-graph-renderer-feature/GUIDE.md) for custom Unity 6 pass code. Use [URP operations](../skills/urp/GUIDE.md) for live asset, renderer and feature inspection or supported wiring. Check the actual pipeline asset and renderer assigned to the target camera.
- **Shader Graph.** Use [the custom HLSL node guide](unity-technologies/shader-graph-create-custom-node/GUIDE.md) for function signatures and node setup. Use [Shader Graph operations](../skills/shadergraph/GUIDE.md) to inspect the graph, blackboard, or perform supported graph edits. Validate graph compilation and material output after the change.
- For custom graph editors use [Graph Toolkit](unity-technologies/build-gtk/GUIDE.md) and check the guide's minimum Unity version. For retro sprite rendering use [2D Pixel Perfect](unity-technologies/2d-pixel-perfect/GUIDE.md).
- Use [graphics patterns](nice-wolf-studio/unity-graphics/GUIDE.md) and [lighting and VFX](nice-wolf-studio/unity-lighting-vfx/GUIDE.md) for rendering code, probes, Particle Systems or VFX Graph. For animated behavior or camera transitions, use [animation and Timeline](nice-wolf-studio/unity-animation/GUIDE.md) or [Cinemachine](nice-wolf-studio/unity-cinemachine/GUIDE.md) with the applicable Editor module.

## Search, assets, and performance

- **Search.** Use [Unity Search](unity-technologies/generate-editor-search-query/GUIDE.md) when building a Search query or opening the Search window. Use [asset](../skills/asset/GUIDE.md), [scene](../skills/scene/GUIDE.md), or [GameObject](../skills/gameobject/GUIDE.md) queries when the agent needs actual project results. Verify the filter and scope before acting on the matches.
- **Import and sprites.** Inspect existing settings through [importer operations](../skills/importer/GUIDE.md). Use [Sprite Editor](unity-technologies/sprite-editor/GUIDE.md) for slicing, pivots or borders, [Sprite Atlas](unity-technologies/manage-sprite-atlas/GUIDE.md) for packing, [sprite structure analysis](unity-technologies/sprite-segment-3x3grid/GUIDE.md) for 3×3 segmentation, and [tile palettes](unity-technologies/create-tile-palette-or-rule-tiles/GUIDE.md) for Tile Palette or Rule Tile authoring. Use [Asset Transformer Toolkit](unity-technologies/asset-transformer-toolkit/GUIDE.md) for its specialized model and point-cloud imports after checking its package requirements.
- **Tilemap 2D.** For a tile level, distinguish the `Grid`, each `Tilemap` layer, its sorting, and collision layer. Use [2D tilemap patterns](nice-wolf-studio/unity-2d/references/tilemaps.md) for runtime painting and collider choices. Check `com.unity.2d.tilemap.extras` before using `RuleTile`; verify the final collision and sorting in the target scene.
- **Audio.** Use [audio design](gamedev-agent-skills/disciplines/audio-design/GUIDE.md) for loudness, ducking, adaptive music and SFX variation. Use [Audio Mixer routing](unity-technologies/audio-setup-mixers/GUIDE.md) for source-to-group assignment and [audio optimization](unity-technologies/optimize-audio/GUIDE.md) for import settings. [Importer](../skills/importer/GUIDE.md) and [optimization](../skills/optimization/GUIDE.md) operations can inspect and apply supported compression changes. Verify the result in its playback context.
- **Audits and frame time.** Start with the requested metric or symptom. For low FPS, stutter or hitches, use [performance optimization](gamedev-agent-skills/disciplines/performance-optimization/GUIDE.md) to distinguish CPU and GPU costs and set a frame budget. Use [Project Auditor](unity-technologies/project-auditor-fixes/GUIDE.md) for its report and rules. Use [profiler](../skills/profiler/GUIDE.md), [optimization](../skills/optimization/GUIDE.md) or [validation](../skills/validation/GUIDE.md) for supported live measurements and checks. Rerun the same measurement or rule after changes.
- Use [2D patterns](nice-wolf-studio/unity-2d/GUIDE.md) for Sprite sorting, Tilemaps or 2D lighting, [audio examples](nice-wolf-studio/unity-audio/GUIDE.md) for spatial playback and routing, and [profiling patterns](nice-wolf-studio/unity-performance/GUIDE.md) to select a measurement before changing an asset or code path.
